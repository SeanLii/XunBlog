Content & Knowledge Architecture

XunBlog 知识内容创作与知识架构规范

Recursive · Modular · Canonical · Progressive · Rigorous
版本 1.0用途：用于后续批量创作、审稿、重构与网站层级导航设计。
核心目标：把每一个知识点写成知识系统中的“可复用模块”，而不是一篇孤立教程。文章只负责当前知识新增的内容；已有机制通过链接递归复用；知识之间同时维护唯一归属关系与可交叉的依赖关系。

1. 总体目标#

XunBlog 的内容体系不是一本线性教材，也不是若干相互独立的文章集合，而是一套可以递归展开的知识系统。读者可以从任意知识节点进入；当正文使用到更基础的概念时，可以沿链接继续下钻，学习该概念自己的 canonical page，再返回当前文章。

因此，每篇文章必须同时满足两类要求：一是它自身要形成完整、连续、层层递进的理解路径；二是它不能重复承担已经属于其他知识节点的完整教学职责。

Article(K) = ΔK + Contextual Use of Dependencies

其中，ΔK 表示当前知识 K 相对于其依赖知识真正新增的定义、结构、机制、性质、变化与限制；依赖知识只在当前语境中被必要地调用，不在本文重新完整教学。

2. 知识系统的形式化模型#

为了同时支持层级导航与跨知识复用，知识系统不应只建一棵树，也不应只建一个无层级的图。更合适的表示是：

G = (V, E_own, E_dep, E_ref)
  • V：全部 canonical knowledge nodes。每个节点对应一个独立、唯一、可复用的知识对象。
  • E_own：归属关系（ownership）。用于决定网站的层级导航。
  • E_dep：依赖关系（dependency）。表示理解当前知识会调用哪些更基础知识。
  • E_ref：关联 / 引用关系（reference）。表示相关但非必要前置的横向连接。

其中，归属关系必须形成稳定的层级结构；依赖关系和引用关系则可以跨越层级自由连接。

2.1 归属树#

若知识 B 首次在知识 A 的体系中被提出，并且 B 可以独立形成 canonical knowledge page，则 B 归属于 A。

parent(B) = A

归属关系用于导航，因此原则上每个非根节点只有一个主要 parent。其他文章即使大量使用 B，也不会改变 B 的归属。

◆
“谁使用 B”与“B 属于谁”是两件不同的事。归属解决导航；依赖解决复用。

2.2 依赖图#

如果知识 C 在解释自身时需要调用 B，则存在依赖边：

C →dep B

这条边只表示 C 的理解依赖 B，不表示 B 应挂到 C 的导航层级下。一个节点可以依赖多个位于不同分支的知识。

2.3 为避免术语混乱#

名称含义是否决定导航层级
归属子知识在某知识体系中首次独立提出、并归属于该 parent 的节点是
依赖知识当前文章理解时调用的更基础模块否
关联知识有助于扩展理解，但不是理解本文的必要条件否

3. 递归知识与模块化复用#

每个知识节点都可以继续递归分解其依赖。假设知识 K 依赖 C₁, C₂, …, Cₙ：

Dep(K) = {C₁, C₂, …, Cₙ}

而任意 Cᵢ 也可以继续拥有自己的依赖集合 Dep(Cᵢ)。因此，读者遇到不理解的术语时，应通过链接进入该知识自己的页面，而不是要求当前文章从最底层重新解释。

这种机制带来的直接结果是：知识只被完整定义一次。

One concept → One canonical page

如果知识 B 被 A、C、D 同时使用，则 A、C、D 都引用 B，而不是各自复制一份 B 的完整原理。这样可以避免重复、版本漂移和不同文章之间的表述冲突。

4. “复用 + 改造”规则#

当知识 C 直接复用了知识 B，但对 B 做了修改、扩展、约束或特化时，C 不应重新解释 B 的完整原理，而应重点解释变化本身。

C = B + ΔC

正文的重点应放在 ΔC：改了什么、为什么改、数学形式如何变化、行为或性质发生了什么变化、代价和限制如何改变。

  • B 中未改变的机制：链接并直接复用，不重复展开。
  • C 相对 B 的新增结构：详细解释。
  • C 相对 B 的删减或约束：详细解释。
  • 改变导致的新性质、新优势、新限制：在对应机制处自然说明。
◆
这条规则是整个网站避免重复内容的关键。一个 variant 页面的价值不在于重新讲 base model，而在于精确说明它相对于 base model 的 delta。

5. 单篇文章的知识边界#

写一个知识 K 时，必须先识别它的知识边界。文章需要回答的不是“和 K 有关的一切”，而是“K 相对于它所复用的知识，究竟新增了什么”。

Knowledge(K) = Reused Knowledge + ΔK

文章正文应集中在 ΔK。对于 Reused Knowledge，只保留理解当前推理所必需的接口信息。

5.1 什么应该留在当前文章#

  • K 的精确定义与它在更大知识体系中的位置。
  • K 自己新增的结构、机制、目标或约束。
  • 这些新增部分对应的数学表达。
  • 新增机制直接产生的性质、能力、代价和限制。
  • K 与其 base knowledge、variants、后续知识之间的关系。

5.2 什么不应该重新展开#

  • 已经属于某个独立 canonical concept 的完整原理。
  • 仅为了照顾零基础读者而重复的底层数学教学。
  • 和当前知识没有直接作用关系的扩展知识。
  • 为了显得“硬核”而加入、但不服务当前推理链的公式或定理。

6. 文章内部必须是“递进链”，不是知识点清单#

模块化解决文章之间的边界；递进结构解决单篇文章内部的学习路径。文章不应以“定义、优点、缺点、训练、应用”这类固定模板机械拼装，而应根据知识本身的逻辑关系确定顺序。

理想结构可以抽象为：

Position → Core Structure → Mechanism → Consequence → Limitation → Extension

更严格地说，正文中的第 i+1 部分应尽可能由第 i 部分自然产生。读者在读完上一部分后，应该自然理解为什么下一部分必须出现。

例如，一个机制 M 导致性质 P，同时引出限制 L：

M ⇒ P, M ⇒ L

那么 P 与 L 应在解释 M 时或紧随其后出现，而不是把所有“缺点”集中在文章末尾。这样限制是由原理自然推出的，而不是附加评价。

6.1 不采用课堂式组织#

文章应像严谨的 technical exposition，而不是教师逐步提问、学生逐步回答的课堂记录。避免把章节组织成大量“为什么……？”“那接下来怎么办？”“假设有一个……”式的教学话术。

例子、直觉和类比可以辅助理解，但不能成为文章的组织骨架。主线必须由知识对象自身的定义、结构、机制与数学关系推动。

7. 数学表达规范#

数学风格应接近 NeurIPS、ICML、ICLR、CVPR 等主流 ML 论文：notation 统一、定义先行、推导紧凑、公式服务论证，而不是把公式当视觉装饰。

7.1 Notation 一致性#

对象推荐记法说明
scalarx, α, η, L普通斜体
vector𝐱, 𝐡, 𝐛统一使用粗体向量
matrix𝐖, 𝐀统一使用粗体矩阵
set / dataset𝒟, 𝒳, 𝒴calligraphic notation
functionfθ, φ, σ函数符号保持一致
layer index𝐡⁽ˡ⁾, 𝐖⁽ˡ⁾用带括号上标明确表示 layer index

当使用上标表示 layer index 时，优先采用带括号形式，例如 𝐡⁽ˡ⁾、𝐖⁽ˡ⁾，避免与幂运算混淆。

7.2 公式只承担必要的数学职责#

  • 定义：明确对象是什么。
  • 推导：证明或导出下一步结论。
  • 目标函数：精确定义 optimization objective。
  • 性质：给出定理、边界、复杂度或结构关系。

7.3 推导采用连续形式#

同一段 algebraic reasoning 应尽量连续展示，而不是一句话配一个碎公式。例如：

y = W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂)

随后正文只解释这个推导对当前知识意味着什么。前置的 matrix multiplication、function composition 等概念默认由其自己的知识页负责。

7.4 Shape 与编号#

  • 变量首次定义且 shape 对当前机制重要时给出 shape；之后不要机械重复。
  • 只有后文需要交叉引用的核心公式才编号；临时推导不必编号。
  • 数学表达要与正文 notation 完全一致，禁止同一对象在不同段落随意换符号。

8. 原理、性质与限制的组织方式#

文章不应单独堆出一个“优点 / 缺点”清单。能力与限制应从机制本身推出。

Mechanism M → Property P → Cost / Limitation L

例如，如果某结构采用 dense connectivity，那么文章应在解释 dense connectivity 后自然说明它带来的全局 feature interaction、参数规模与缺少特定 structural bias，而不是最后再补一句“缺点：参数多”。

这种写法要求每一个评价都能回溯到对应的结构或数学事实，避免空泛描述。

9. 语言与术语规范#

整体语言应以中文承担解释、推理和连接，同时保留真正具有领域意义的 English technical terms。目标是提高连续阅读体验，而不是追求“全中文”或“全英文”。

首次出现的关键术语应确保语义清楚，但不要因为一个术语是英文就强行翻译，也不要在全文重复“中文（英文）”造成阅读负担。

9.1 风格目标#

  • 正式、技术性、可读，但不是科普故事。
  • 避免过度口语化和教师式提示语。
  • 避免抽象、文学化、故作高深的措辞。
  • 技术难度可以高，但语言本身不应无谓增加理解成本。
  • 标题应以知识对象和自然结构为主，避免大量问句式标题。

10. 原始来源与事实边界#

涉及具体模型、算法或论文贡献时，核心机制必须以原论文为第一依据。官方代码、官方项目页和作者补充材料可用于确认实现细节，但应区分“论文定义”“官方实现”“常见后续做法”。

若某个结论来自后续工作，而不是原始论文，不应把它写成原论文自身的设计。对于存在多个版本的模型，应明确当前文章讲的是哪一个版本，以及相对前一版本的 Δ。

11. Canonical page 与链接规则#

每个具有独立定义、机制和复用价值的概念，应有且只有一个 canonical page。文章中第一次需要该概念时，通过术语链接指向该 page。

是否应该独立成页，可用下面的问题判断：

  • 它能否脱离当前文章，形成独立、完整的知识对象？
  • 它是否会被多个其他知识复用？
  • 它是否具有自己的定义、机制、数学性质或重要变体？
  • 把它拆出去后，当前文章是否仍能保持连续，而不会丢失自己的核心知识？

如果多数答案为“是”，它通常应该成为独立 canonical node。

12. 每篇文章创作前的内部工作流#

在真正开始写正文前，作者必须先完成知识建模，而不是边写边决定边界。推荐流程如下。

  1. 确定当前知识 K 的精确定义：它是什么，不是什么。
  2. 确定 K 在知识体系中的唯一 owner / parent，用于层级导航。
  3. 识别 Dep(K)：理解 K 所调用的依赖知识。
  4. 识别 K 是否复用了某个 base knowledge；如果是，明确 ΔK。
  5. 识别 K 内部是否首次提出新的可独立知识节点，并为这些节点建立归属关系。
  6. 规划正文递进链：每一节为什么在这里出现，下一节如何由上一节自然推出。
  7. 确定必要的数学 notation、核心公式和需要链接的术语。
  8. 写正文，只展开 K 自身的知识增量；依赖知识只保留当前语境需要的接口。
  9. 检查性质与限制是否已经在对应机制处自然说明。
  10. 检查是否存在重复教学、越界展开、无意义公式、知识归属冲突或断裂的推理链。

13. 审稿与验收标准#

维度通过标准
知识边界文章详细解释的内容确实属于当前知识；依赖知识没有被重新完整教学。
归属关系当前节点有明确 parent；新提出的独立知识有清楚、唯一的归属。
模块复用已有知识通过链接复用；variant 重点解释 delta，而不是复制 base。
递进结构章节之间存在明确的逻辑 / 因果关系，不是知识点列表。
数学严谨性notation 统一、定义明确、公式必要、推导与结论匹配。
解释性公式之后能说明它对当前知识意味着什么，但不重新教授 prerequisite。
性质与限制限制能从对应机制自然推出，不是文章末尾附加的优缺点清单。
可读性中文叙述连贯；必要 technical terms 保留英文；无明显课堂式或科普式腔调。
事实依据模型与算法内容以原论文 / 官方来源为核心，不混淆原始设计和后续变体。
链接完整性正文中被依赖且值得独立成页的知识都有 canonical link 入口。

14. 典型反模式#

14.1 把当前文章写成“从零开始”的大教程#

错误：为了让任何读者都能直接看懂，在 MLP 页面重新完整讲 neural network、matrix multiplication、activation、backpropagation。

正确：当前文章只保留这些知识在 MLP 中的必要接口；读者不会时通过链接下钻。

14.2 把相关知识全部塞进当前文章#

错误：认为“和当前主题相关”就应该详细讲。结果是页面边界不断膨胀，同一概念在多篇文章重复出现。

正确：判断它是否属于 ΔK；如果不是，则链接到它自己的 canonical page。

14.3 Variant 重新讲 Base Model#

错误：C 是 B 的改进版，却先花一半篇幅重讲 B。

正确：把 B 当作已定义模块，正文集中于 ΔC。

14.4 先写“优点 / 缺点”，再找理由#

错误：把评价和机制分离。

正确：让结构、公式或设计选择先出现，再自然推出它带来的能力和限制。

14.5 为了硬核而堆数学#

错误：加入与主线无关的复杂公式。

正确：数学只用于定义、推导、证明或刻画当前知识的必要性质。

15. 一个抽象示例#

假设知识 A 首次提出独立知识 B，因此：

parent(B) = A

后来知识 C 使用 B，并对 B 做修改 ΔC：

C = B + ΔC

则 C 的文章应：

  • 链接到 B，默认 B 的原理已经由其 canonical page 定义。
  • 详细定义 ΔC。
  • 说明 ΔC 为什么需要出现。
  • 给出 ΔC 对原有数学结构、数据流、参数、training / inference 行为或性质的改变。
  • 从这些变化自然推出新的能力、代价和限制。
  • B 仍然归属于 A；C 对 B 的依赖不会改变 B 的导航位置。

16. 最终原则#

◆
每篇文章不是一篇孤立教程，而是知识图中的一个 canonical module。归属树决定“这个知识属于哪里”，依赖图决定“这个知识需要调用什么”，ΔK 决定“这篇文章真正应该详细讲什么”，递进链决定“读者如何顺着正文真正学会它”。
Good Article = Correct Boundary + Recursive Reuse + Clear ΔK + Progressive Reasoning + Rigorous Math

后续批量创作时，应先建模知识，再写文章；先确定 ownership / dependency / delta，再决定正文结构。只要知识边界和依赖结构正确，网站内容才能长期保持一致、可维护、可扩展。
